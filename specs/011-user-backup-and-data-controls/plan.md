# Implementation Plan: User-Scoped Backups, Self-Service Password Change, and Personal Data Controls

**Branch**: `011-user-backup-and-data-controls` | **Date**: 2026-10-02 | **Spec**: [spec.md](file:///home/rhoribe/lab/minhashoras/specs/011-user-backup-and-data-controls/spec.md)

**Input**: Feature specification from `specs/011-user-backup-and-data-controls/spec.md`

## Summary

Enforce strict administrator-only boundaries for system-wide database backups, routines, and full restoration, while granting all users access to an individual personal data export ("Backup Pessoal" in structured JSON format). Implement voluntary self-service password changes in settings requiring current password validation and password complexity checks. Implement a dedicated personal records reset mechanism ("Zerar Meus Registros") that purges only the calling user's overtime and compensation records and resets their balance to zero without deleting their login account.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Principle I: Mobile-First & Cross-Platform PWA**:
  - *Pass*. All dialogs (password change modal, records reset modal, personal backup trigger) are responsive, centered with backdrop-blur, and provide touch targets $\ge 44 \times 44\text{ px}$ (`min-h-touch min-w-touch`).
- **Principle II: Offline-First Operation & Deterministic Sync**:
  - *Pass*. Personal records reset purges both server records and local IndexedDB entries for `user_id` synchronously, preventing deleted entries from resurrecting on sync. Personal backup can export local state when offline.
- **Principle III: Minimalist Architecture & Resource Efficiency**:
  - *Pass*. Reuses existing Fastify routing, scrypt hashing, and SQLite queries without adding external queue or cloud dependencies. Keeps RAM usage well within the 150MB container bound.
- **Principle IV: Reliable & Lightweight Database Persistence**:
  - *Pass*. Atomic SQLite transactions for records reset and user updates prevent inconsistent or orphaned states.
- **Principle V: Containerized Single-Node Deployment**:
  - *Pass*. Fully compatible with existing single-node Docker setup and SQLite database file persistence.
